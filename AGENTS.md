# AGENTS.md

Guidance for AI agents working in this repository.

## What this is

A personal NixOS configuration using a Flake. Single machine target (hostname `toshiba`, an old 2010 laptop), `x86_64-linux`, running **nixpkgs master** — expect heavy recompilation, no binary cache guarantee. It doubles as a reference config, not a template.

Design values (see README): simplicity, reproducibility, keyboard-driven, terminal-centric (TMUX/Foot), low resource usage.

## Layout

```
flake.nix                   # inputs + outputs; nixosConfiguration "toshiba"; home-manager wired in
flake.lock                  # lockfile — commit it, don't hand-edit
hosts/toshiba/              # per-host NixOS modules (configuration.nix + modules/)
  configuration.nix         # imports the module list
  hardware-configuration.nix# generated, don't touch by hand
  modules/                  # agenix, boot, desktop, kernel, locale, network, packages,
                            # programs, services, settings, users, virtualisation
home/                       # home-manager module tree
  home.nix                  # top-level home-manager config
  modules/                  # dotfiles, fish, firefox, foot, git, gtk, lazyvim, mimeapps,
                            # noctalia, niri, packages, services, spicetify, ssh, starship,
                            # symlink, tmux, wf-recorder, zsh, formatter, dotfiles
dotfiles/                   # dotfiles symlinked out via home/modules/symlink.nix
                            # (yazi uses mkOutOfStoreSymlink; niri is declarative in
                            #  home/modules/niri.nix via niri-flake; fastfetch is declarative in
                            #  home/modules/fastfetch.nix)
secrets/                    # agenix-encrypted *.age — SENSITIVE
wallpaper/                  # wallpaper assets (purely decorative, no semantics)
update.py | update.sh       # manual rebuild/update workflow (python and bash variants)
graphify-out/               # GENERATED knowledge-graph artifacts — do not hand-edit
```

## Conventions

- **Nix**: `nixfmt` for formatting, `statix` + `nil` for linting/IDE, `shellcheck`/`shfmt` for shell. Run `nixfmt` on every `.nix` file you touch.
- **Secrets**: everything under `secrets/` is agenix-encrypted. Never read, decrypt, print, or commit plaintext secrets. It is fine to reference `agenix` secrets by name in Nix modules (e.g. `hosts/toshiba/modules/agenix.nix`).
- **Wallpapers**: treat `wallpaper/*` as decorative assets with no semantic meaning.
- **graphify-out/** is generated by the `/graphify` skill (graph.json, GRAPH_REPORT.md, graph.html, cache/, manifest.json, cost.json). Do not edit by hand; rerun graphify instead.
- **Commits**: the update scripts auto-commit with messages like `update tanggal <date>`; keep commits small and focused otherwise.

## Common commands

```bash
# Build/evaluate the flake for this machine
nixos-rebuild dry-build --flake ~/nixos-config#toshiba

# Apply
sudo nixos-rebuild switch --flake ~/nixos-config#toshiba

# Update inputs (this is the dangerous/long one — nixpkgs master rebuilds a lot)
nix flake update --flake ~/nixos-config

# Or the one-shot interactive flow (commits, dry-build, prompt, switch, nvd diff)
./update.py        # python variant
./update.sh        # bash variant

# Format / lint Nix
nixfmt <file.nix>
statix check

# Regenerate the knowledge graph
/graphify .        # or: graphify query "..." for questions
```

## Gotchas

- `nixpkgs` tracks **master** (see the commented-out `nixpkgs-unstable` line in `flake.nix`). Updating pulls brand-new packages; things can break and builds take hours.
- The inverse: inputs are deliberately *not* fully follows-pinned in places (NUR, catppuccin, lazyvim) — check `flake.nix` before assuming an input is pinned.
- This machine runs a custom/unusual kernel stack and wireless hardening is disabled. Don't copy `hosts/toshiba/modules/kernel.nix` blindly to other machines.
- Hardware config is machine-generated; edit via `nixos-generate-config` if the hardware changes.
- The update scripts assume a git repo at `~/nixos-config` and the hostname matching the flake's machine attr (here `toshiba`).

## Matrix / CI

None. Validation is `nixos-rebuild dry-build` and `statix check`.
